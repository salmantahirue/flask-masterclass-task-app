Problem Statement: Task Management System

Understanding the real-world problem we're solving with Flask.

The Real-World Scenario

Teams and individuals need a place to track work: what to do, when it is due, and whether it is done. A Task Management System lets users:

  • Create an account and log in
  • Add tasks (title, description, status, priority, due date)
  • Group tasks into categories (e.g. Work, Personal)
  • Filter and view tasks by status or priority
  • Edit and delete tasks and categories

The system must be reliable (data persists in a database), secure (users must log in), and extensible (easy to add features like search or tags).

Why This Problem is Perfect for Learning Flask

This is a real-world problem that naturally uses core Flask and web concepts:

1. Multiple Entity Types

Users, Tasks, and Categories—each needs a model and routes (CRUD).

2. HTTP & REST

GET for listing, POST for creating, PUT for updating, DELETE for deleting—with proper status codes.

3. Authentication

Session-based login for the web UI; JWT for the REST API.

4. Templates & Forms

Jinja2 for HTML; Flask-WTF for validation and CSRF protection.

Detailed Requirements

1. User Management

  • Registration: Email, password, optional username. Password hashed (bcrypt).
  • Login: Session-based for web UI; returns JWT for API.
  • Logout: Clear session / client discards token.

2. Task Management

  • Create: Title, description, status (pending/in progress/completed), priority, due date, optional category.
  • Read: List tasks (with filters: status, priority, category); view single task.
  • Update: Edit any task field.
  • Delete: Remove a task (owned by current user).

3. Categories

  • Create, read, update, delete categories.
  • Tasks can belong to one category; categories are per user.

4. Data & API

  • SQLite (or PostgreSQL) via SQLAlchemy ORM.
  • REST API under /api/auth, /api/tasks, /api/categories with JWT.
  • Web UI under /app (login, dashboard, tasks, categories) with session auth.

The "Tutorial" vs. "Architect" Mindset

Beginner Way

One big app.py with all routes.

No blueprints, no factory, no service layer.

Architect Way

Application factory and Blueprints (auth, tasks, categories, web).

Models, services, and clear separation of concerns.
